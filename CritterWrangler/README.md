# Critter Wrangler

A teal robo-miner fitted with a Rancher's net gun. It automatically wrangles
surplus critters in its room and leaves them bagged for a Duplicant to carry to a
Critter Drop-Off.

Sibling to [Critter Turret](../CritterTurret), which is the lethal version.
Neither mod requires the other; install either or both.

## What it does

- Mounts on floor, wall or ceiling, rotatable, with a directional firing
  rectangle and line-of-sight checks — the same range visual the Robo-Miner uses.
- Counts **each species in the room separately** against one population
  threshold, so an overcrowded species is thinned without touching the others.
  Babies are their own rows with their own counts.
- **Catches the critter itself.** It doesn't flag one for a Rancher to come and
  wrangle; it fires the net and the critter ends up bagged on the ground. No
  Ranching skill is consumed. Duplicants still do the hauling.
- Sends a **green Automation signal** once every selected species is at or below
  the threshold.
- Works submerged. Not industrial machinery, so it won't disqualify a room.

Critters that can never be wrangled — Morbs, adult Beetas, Shockworms — are
skipped and left out of the count, so ticking one is a no-op rather than a jam.

## How the discharge works

`CritterWranglerBrain.Discharge` reproduces `Capturable.OnCompleteWork(worker)`,
which is the method a Rancher's capture chore ends in:

1. work out the landing cell (step up one if the critter was inside solid ground)
2. `Capturable.MarkForCapture(false)` — clears any hand-placed mark and cancels
   the chore, so nobody walks over to wrangle something already wrangled
3. `Baggable.SetWrangled()`
4. move the bundle to that cell on the `Ore` scene layer

That method is `protected`, hence reproduced rather than called.

## Building

```sh
./build.sh
```

Compiles to `dist/` and deploys to `mods/Dev/CritterWrangler`. **ONI only loads
mod DLLs at startup** — fully quit and relaunch to pick up a new build.

### Shared sources

`CritterTargetingBrain.cs` and `CritterBuildingTemplate.cs` live in
`../CritterTurret/src` and are imported at build time, with their namespace
rewritten from `CritterTurret` to `CritterWrangler`.

Two separately-shipped mods must not both define
`CritterTurret.CritterTargetingBrain`: a user can install either or both, and
identically-named types across two loaded assemblies invite trouble in anything
that resolves types by name — KSerialization does.

`build.sh` fails loudly if a shared file still mentions `CritterTurret` after the
rewrite, which means it has taken a dependency on turret-specific code and needs
splitting differently. Keep those two files free of references to anything
outside themselves.

The art is generated by `../CritterTurret/tools/gen_red_kanim.py`, which writes
both recolours into their respective mods' `anim/` trees.
